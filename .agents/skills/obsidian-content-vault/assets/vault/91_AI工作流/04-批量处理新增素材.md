# 批量处理新增素材

执行入口：“处理新增素材”。配套 [[91_AI工作流/AI归档协议|AI 归档协议]] 与 [[00_导航/集中确认清单|集中确认清单]]。

## 执行步骤
1. 读取首页、归档协议和集中确认清单的处理台账。
2. 仅枚举「02_X素材」、「09_评论」及其子目录，以及「01_收件箱/原始素材」内的 Markdown，排除索引和说明文档。兼容插件的 source、handle、published 等属性，不要求它生成中文字段。
3. 原帖按帖子 ID 或来源 URL 去重，单条评论按评论 ID 或评论 URL 去重，评论集按原帖 ID 与采集批次区分；再比较实际文件内容的 SHA-256。评论集中的评论需逐条去重，不能把不同评论都按原帖 ID 合并，也不能把历史快照重复计为新意见。相同来源且相同内容已有处理结果时跳过；同源多份副本报告重复，不删除。
4. 默认每次处理最多 10 篇未处理素材，按候选文件修改时间由早到晚，路径作为同时间排序项。先报告本批范围和剩余数；用户明确范围优先。没有新增时直接报告，不创建空卡片。
5. 对每篇实际读到的完整正文，按 [[91_AI工作流/01-单篇素材提炼|单篇提炼]] 生成 0—3 张候选提炼卡。图片、评论、线程未读取则明确说明，不补造内容。
   对评论文件，同时读取已提供的原帖与父评论上下文，区分评论者、原作者与 AI 解读；原帖未提供则说明缺口，不擅自联网补采。可提炼问题、分歧、场景和候选需求，但部分可见评论不代表全部受众。提炼卡链接评论文件及实际读取的原帖，集中确认时保存两者的真实哈希。
6. 有独立判断价值时可另写少量候选观点，用个人观点模板，但“观点归属”保持“AI候选”、“本人确认”为 false；不得代写个人经历或宣布用户认同。
7. 将候选自动保存到「01_收件箱/AI待确认」，使用稳定文件名并排他创建。同名时先检查现有内容，保留人工修改，不覆盖。
8. 在集中确认清单中追加未勾选的操作项，附摘要、原文链接、目标目录、真实候选与来源哈希；写入实际处理台账。没有可复用点则仅记台账和理由。
9. 验证写入文件、来源链接和清单链接；仅报告实际成功保存的数量、待确认位置、剩余素材与缺口。

## 失败与重试
正文缺失、链接无法对应、同名冲突或文件同时被修改时暂停该项，保留其他已完成项并说明原因。候选已写成功但清单更新失败时，重试先核对文件再补清单，不生成重复副本。

自动保存候选不需要逐篇确认；本人观点是否成立和是否保留由集中确认完成。原文不因本步骤被移动或改写。
