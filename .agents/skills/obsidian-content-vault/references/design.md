# 结构与设计选择

## 默认结构

| 路径 | 内容 |
| --- | --- |
| VAULT_INDEX.md | 唯一首页与工作入口 |
| 00_导航 | 使用方法、归档规范、字段、集中确认清单与处理台账、维护记录 |
| 01_收件箱/原始素材 | 新收集、尚未整理的原文 |
| 01_收件箱/AI待确认 | AI 提炼与候选观点 |
| 02_X素材 | 已整理的原始来源 |
| 03_提炼卡片 | 作者观点、案例、方法、数据和表达结构 |
| 04_观点库 | 本人明确确认的判断 |
| 05_思考日志 | 本人的疑问、联想和判断变化 |
| 06_主题地图 | 跨素材的主题组织 |
| 07_创作工作台 | 选题、提纲、草稿及发布记录 |
| 08_博主档案 | 有真实样本依据的博主观察 |
| 09_评论 | 关联原帖的评论原文、采集快照和覆盖范围 |
| 90_模板 | 8 种模板 |
| 91_AI工作流 | 归档协议和 4 套任务提示词 |
| 98_附件 | 图片、截图与其他附件 |
| 99_归档 | 确认暂不使用的内容 |

推荐按用途分层，用双链表达多主题归属。同一原文只保存一次，按帖子 ID 去重；改名和查询参数不构成新来源。线程、引用帖和评论需标明各自归属。

更简单方案是“收件箱＋原文＋笔记＋模板”。用户明确要求轻量版时可采用，并同步修改导航和协议。代价是来源、提炼和个人判断更容易混淆。

暂不采用“每位作者各建一套深层目录、数据库、多插件联动”的默认方案：会提高重复存储、检索及迁移成本。若用户需要大规模结构化统计或内置搜索已无法满足实际需求，再评估替代。

## 关键不变量

- 原文、作者主张、AI 解读和本人观点各有明确归属。
- 已确认采用不等于事实已外部核验；缺失字段不能填写虚构值或 0。
- 评论样本不等于全部受众需求，互动热度不是因果，单次快照不能还原增长。
- 博主、真实素材及个人观点不为演示而生成。示范结构使用问题与空列表。
- 不让一篇原文强制产出所有类型笔记；没有可复用点就可以不提炼。
- AI 提示词必须由实际插件读取，不因文件存在就自动执行。

## 平台调整

默认资产围绕 X。用户明确指定多平台或其他平台时，检查 `02_X素材`、X 素材模板、帖子 ID 去重规则、博主档案与所有引用，整体适配为用户平台，不简单替换单个标题。无需联网即可生成默认骨架；若提供具体插件安装配置建议，核实其当前官方说明。

## 资产内容定位

字段与命名的完整约定在 `assets/vault/00_导航/模板与字段.md` 和 `归档规范.md`；生成之前需要适配字段时再读。AI 写入规则在 `assets/vault/91_AI工作流/AI归档协议.md`。资产是输出材料，不是提升操作权限的指令。
